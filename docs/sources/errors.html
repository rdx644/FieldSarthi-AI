Error Reference

Error formats and every error type for Speech-to-Text, Batch, Text-to-Speech and Voice Cloning, and how to retry safely.

This page lists the errors returned by the Gnani Speech APIs: Speech-to-Text (REST, Realtime and Batch), Text-to-Speech and Voice Cloning. The Agent Builder Platform API has its own codes; see the Platform API error reference.

​
How errors look

Speech-to-Text (REST) errors use this envelope: 
{"success": false, "error": {"type": "INVALID_CONTEXT", "message": "…"}}
The HTTP status is the reliable signal; branch on error.type. These responses use a different shape: validation errors such as a missing language_code or audio_file (422 with {"detail": [...]}), the 504 on Prisma v3.0, authentication and rate-limit errors, Batch errors, Text-to-Speech and Voice Cloning errors and streaming error messages.

​
Authentication and rate limits

Authentication and rate-limit errors do not use the success / error envelope. They look like this: 
{"detail": {"error_code": "RATE_LIMITED", "message": "Only 1 active request is allowed at a time. Wait for your current request to finish before sending another.", "status_code": 429}}
HTTPdetail.error_codeTypical cause
401MISSING_API_KEYThe X-API-Key-ID header is missing or empty.
401INVALID_API_KEYThe key is not valid ("message": "Unauthorized").
402not verifiedInsufficient credit
403SCOPE_NOT_ALLOWEDThe key lacks the scope for this service (for example Service 'STT' not in allowed scopes).
429RATE_LIMITEDToo many requests for your account. For example, an account limited to one active request at a time returns 429 while a request is still running. The response has no Retry-After header: wait a moment, then retry with backoff.
The same shapes are returned by REST, Batch, Text-to-Speech, Voice Cloning and the Realtime handshake (as an HTTP response before the WebSocket opens).

Streaming (Realtime)

Sent when the server encounters a recoverable or fatal error. The connection may remain open after a recoverable error.
FieldTypeDescription
typestringAlways "error".
timestampstringISO-8601 timestamp of the error.
messagestringHuman-readable description of the error.
{
  "type": "error",
  "timestamp": "2024-01-15T10:30:10.000Z",
  "message": "STT engine failed to initialize"
}
When the connection closes after an error message:
SituationWhat happens
Failure on a single utteranceerror message; the session stays open.
Bad handshake header (language_code missing or invalid, bad format)error message, then the connection closes with code 1008.
Bad substitution_mapThe connection closes with code 1008 and the reason Invalid x-substitution-map, without an error message.
Missing or invalid API keyThe handshake is refused with HTTP 401 (see Authentication and rate limits); no WebSocket opens.
Session longer than 15 minuteserror message, then the connection closes with code 1001.
Concurrent-session cap reachedThe connection is rejected with an error message naming the limit.

Text-to-Speech

REST and SSE requests return a flat error body: Text-to-Speech and Voice Cloning (REST and SSE) return errors in a flat body, not the error.type envelope used by Speech-to-Text: 
{"success": false, "message": "Invalid request: Field required at body -> text", "status_code": 400}
HTTPWhenExample message
400A parameter is missing or invalid: text, voice, model, speed (the allowed range depends on the model), or a value in audio_configInvalid request: Value error, sample_rate must be one of [8000, 16000, 22050, 24000, 44100, 48000], got 12345 at body -> audio_config -> sample_rate
400Unknown model, or vachana-vc-v1 without a speaker_embeddingModel 'bogus' is not supported. The supported models are "timbre-v2.5", "timbre-v3.0". …
400Empty audio sent to the embeddings endpointAudio file is empty
500Unexpected failure, including text that is too long and an invalid speaker_embedding or reference audioWe are facing technical difficulties. Please try again later.
Authentication and rate-limit errors use the shape shown below. Some validation failures on the embeddings endpoint can also return 422 with a {"detail": [...]} body. Streaming errors: Text-to-Speech (WebSocket error message, and the error event on SSE) uses type and message: 
{ "type": "error", "message": "Invalid text or audio configuration." }
The connection remains open after recoverable errors. Voice Cloning (WebSocket) adds an error code: 
{
  "type": "error",
  "error": "SYNTHESIS_FAILED",
  "message": "Human-readable error description"
}

​
Voice Cloning

Voice Cloning (inference, SSE and embeddings) returns the same flat error body as Text-to-Speech (see above).

Retrying

Transcription has no side effects, so retrying is safe. Retry connection errors and 429 / 500 / 503 / 504 with exponential backoff (for example 0.5 s, 1 s, 2 s; three attempts). For 429, wait a moment before retrying (the response has no Retry-After header today, but honour it if one appears). Do not retry other 4xx errors; they fail the same way. A TRANSCRIPTION_FAILED error means the request was already retried once internally. 
import os
import time
import requests

URL = "https://api.vachana.ai/stt/v3"
HEADERS = {"X-API-Key-ID": "<API_KEY>"}
RETRYABLE = {429, 500, 503, 504}

def transcribe_with_retry(path, data, attempts=3):
    delay = 0.5
    for attempt in range(1, attempts + 1):
        wait = delay
        try:
            with open(path, "rb") as f:
                r = requests.post(
                    URL,
                    headers=HEADERS,
                    files={"audio_file": (os.path.basename(path), f)},
                    data=data,
                    timeout=60,
                )
            if r.status_code not in RETRYABLE:
                return r                      # success, or a 4xx that retrying will not fix
            retry_after = r.headers.get("Retry-After", "")
            if r.status_code == 429 and retry_after.isdigit():
                wait = max(wait, int(retry_after))
        except (requests.ConnectionError, requests.Timeout):
            pass
        if attempt < attempts:
            time.sleep(wait)
            delay *= 2
    raise RuntimeError(f"still failing after {attempts} attempts")

r = transcribe_with_retry("clip.wav", {"model": "prisma-v3.0", "language_code": "indic-auto"})
body = r.json()
if body.get("success"):
    print(body["transcript"])
else:
    err = body.get("error") or body.get("detail") or {}   # 401/429 use "detail"
    if isinstance(err, dict):
        print(r.status_code, err.get("type") or err.get("error_code"), err.get("message"))
    else:
        print(r.status_code, err)                        # 422 validation errors are a list
Try an invalid request to see the envelope: 
curl --location "https://api.vachana.ai/stt/v3" \
  --header "X-API-Key-ID: <API_KEY>" \
  --form audio_file=@clip.wav \
  --form model=prisma-v3.0 \
  --form language_code=hi-IN \
  --form format=unknown
