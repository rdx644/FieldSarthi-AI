​
Overview

The REST endpoint transcribes an audio file in a single synchronous HTTP request and returns the transcript immediately. It is best suited for short, pre-recorded audio clips.
Use caseRecommended endpoint
Short clips ≤ 30 sThis endpoint
Live microphone / real-time audioSTT Realtime (WebSocket)
Large files or bulk jobsSTT Batch

​
Endpoint

POST https://api.vachana.ai/stt/v3
Content-Type: multipart/form-data

​
Authentication

Pass your API key in the request header.
HeaderTypeRequiredDescription
X-API-Key-IDstringYesYour Gnani API key. Obtain one from the Gnani APIs dashboard.
X-API-Request-IDstringNoYour correlation id, echoed as request_id. Generated if omitted.

​
Request parameters

All parameters are sent as multipart/form-data fields.
​
file
required
Audio file to transcribe. Supported formats: WAV, MP3, OGG, FLAC, AAC, M4A. Maximum duration: 30 seconds.
​
string
Model to use. Send prisma-v3.0 for Prisma v3.0. Leave it out to use Prisma v2.5, the default model (the response reports it as prisma-v2.5).
​
string
required
A language code from Supported Languages. Prisma v2.5 accepts one language. Prisma v3.0 also accepts indic-auto, or a comma-separated list of 1–4 languages, for example hi-IN,en-IN. The model listens for the languages you send first, and the transcript follows the language actually spoken. They are hints, not a lock. See Language detection. Required, except with format=transliterate on prisma-v3.0, where it is optional and defaults to indic-auto.
​
enum
default:"verbatim"
verbatim — raw spoken-form output. transcribe — enables Inverse Text Normalization (ITN): numbers, currency, dates, and phone numbers are written in their conventional form. See ITN below. codemix (prisma-v3.0 only) keeps English words in Latin script and mostly spells numbers as words. transliterate (prisma-v3.0 only) writes the whole transcript in Latin letters, for example तो ठीक है becomes to theek hai; see Romanised output. With prisma-v3.0, the default when format is omitted depends on the request; see Output styles.
​
boolean
default:"false"
When format=transcribe, set true to render digits in the native script of the target language (e.g. ₹५,००० instead of ₹5,000 for Hindi). Has no effect when format=verbatim. No effect on prisma-v3.0 for this endpoint.
​
string
prisma-v3.0: words or short phrases to favour, as a JSON array (["खाता","HDFC Bank"]) or comma-separated, up to 200. See Context.
​
string
prisma-v3.0: what the recording is about. Any non-empty text, up to 1,600 characters (no minimum).
​
string
prisma-v3.0: the transcript of the clip just before this one. Any non-empty text (no minimum); the last 600 characters are kept. Applies to the first part of the audio only.
​
string
prisma-v3.0: a JSON array or comma-separated names, 1–4.
You can send any combination of keyterms, topic, previous_text and speaker_names, from none to all four. A value outside its limit returns 400 INVALID_CONTEXT. See Context.
​
boolean
default:"false"
Set to true to enable post-transcription find-and-replace. When enabled, all patterns listed in substitution_map are replaced in the final transcript text after recognition and ITN. Has no effect when false (default) — the substitution_map field is ignored entirely.
​
string
A JSON-encoded list of substitution rules applied to the transcript after recognition and ITN. Only evaluated when enable_substitution=true. Maximum 10 rules.Each rule is an object with two fields:
FieldTypeDescription
patternsstring[]One or more strings to find. Matching is case-insensitive and respects Unicode word boundaries, so "ok" matches "OK" and "Ok" but not "okay".
replacementstringThe string to substitute for every matched pattern in this rule.
[
  {"patterns": ["okay", "ok", "alright"], "replacement": "acknowledged"},
  {"patterns": ["rupees", "rs"],           "replacement": "INR"}
]
Rules are applied in a single pass — there is no risk of one replacement being re-matched by a later rule. Longer phrases take priority over shorter ones (e.g. "New Delhi" matches before "Delhi").
Substitution runs on the final client-visible transcript only. Billing records always carry the original raw transcript regardless of this setting.
​
string
Prisma v2.5. Words to boost during recognition — brand names, product names, or other terms the model tends to miss. Up to 100 words, as a JSON array (["EMI","Prisma"]) or comma-separated (EMI,Prisma). Each entry must be a single word of letters only (no spaces, digits, punctuation, or symbols). Only takes effect together with a positive bias_score. See Word Boosting below. On prisma-v3.0, bias_list is the older name of keyterms and is used only when keyterms is not sent.
​
number
Prisma v2.5 only; ignored by prisma-v3.0. Boost strength for bias_list. One of 0.0, 0.5, 1.0, 1.5, 2.0. 0.0 or omitted turns boosting off.

Error responses

Speech-to-Text (REST) errors use this envelope: 
{"success": false, "error": {"type": "INVALID_CONTEXT", "message": "…"}}
The HTTP status is the reliable signal; branch on error.type. These responses use a different shape: validation errors such as a missing language_code or audio_file (422 with {"detail": [...]}), the 504 on Prisma v3.0, authentication and rate-limit errors, Batch errors, Text-to-Speech and Voice Cloning errors and streaming error messages.

Authentication and rate limits

Authentication and rate-limit errors do not use the success / error envelope. They look like this: 
{"detail": {"error_code": "RATE_LIMITED", "message": "Only 1 active request is allowed at a time. Wait for your current request to finish before sending another.", "status_code": 429}}
HTTPdetail.error_codeTypical cause
401MISSING_API_KEYThe X-API-Key-ID header is missing or empty.
401INVALID_API_KEYThe key is not valid ("message": "Unauthorized").
402not verifiedInsufficient credit
403SCOPE_NOT_ALLOWEDThe key lacks the scope for this service (for example Service 'STT' not in allowed scopes).
429RATE_LIMITEDToo many requests for your account. For example, an account limited to one active request at a time returns 429 while a request is still running. The response has no Retry-After header: wait a moment, then retry with backoff.
The same shapes are returned by REST, Batch, Text-to-Speech, Voice Cloning and the Realtime handshake (as an HTTP response before the WebSocket opens). See Error Reference for streaming, Batch and retry guidance.

Python — Auto-detect the language
import requests

    r = requests.post(
        "https://api.vachana.ai/stt/v3",

body = r.json()

Inverse text normalization (ITN)

This section describes Prisma v2.5. On Prisma v3.0 the model formats numbers itself when format=transcribe; see Output styles. ITN converts the spoken-form output of the ASR engine into the conventional written form a reader expects — numbers become digits, currency gets the ₹ symbol, dates are formatted, and phone numbers are compacted — all in one pass, immediately after transcription. How to enable: Set format=transcribe in the request body.

​
What ITN normalizes

​
1 — Cardinal & ordinal numbers

Whole numbers and positional ranks are formatted using Indian comma grouping (groups of 2 after the first 3 digits).
Spoken input (ASR)Written output (ITN)Rule
दो हज़ार2,000Indian comma grouping
पाँच लाख बीस हज़ार5,20,000Lakh-scale grouping
उन्नीस सौ चौरानवे1,994Hundred-base year form
five lakh5,00,000English lakh convention
पहला / twenty first1st / 21stOrdinal suffix

​
2 — Currency & money

All Indian currency expressions — including paise fractions and lakh/crore scales — are formatted with the ₹ symbol and Indian comma grouping.
Spoken input (ASR)Written output (ITN)Rule
पाँच सौ रुपये₹500₹ + amount
तीन रुपये पचास पैसे₹3.50₹ + rupees.paise
दस लाख रुपये₹10,00,000₹ + lakh grouping
I need five thousand rupees₹5,000English India pipeline

​
3 — Dates

Spoken input (ASR)Written output (ITN)Rule
बीस जनवरी दो हज़ार पच्चीस20 जनवरी 2025DD Month YYYY (hi)
fifteenth january twenty twenty five15th January 2025Ordinal Month YYYY (en)

​
4 — Times

Indian time-of-day words (सुबह, दोपहर, शाम, रात) automatically map to 24-hour HH:MM output.
Spoken input (ASR)Written output (ITN)Rule
सुबह पाँच बजेसुबह 05:00सुबह = AM
शाम पाँच बजेशाम 17:00शाम = evening (16–20 h)
रात के दस बजेरात 22:00रात = night (20–24 h)
meeting at five fifteen in the eveningmeeting 17:15 in the eveningen — 24-hour

​
5 — Phone numbers & PIN codes

Digit streams are concatenated into compact numeric strings. 10-digit streams → mobile number; 6-digit streams → PIN. Repeat prefixes (double/डबल, triple/ट्रिपल) are expanded.
Spoken input (ASR)Written output (ITN)Rule
नौ आठ सात छह पाँच चार तीन दो एक शून्य987654321010 digits → phone
एक एक शून्य शून्य शून्य एक1100016 digits → PIN
डबल आठ नौ शून्य एक दो तीन चार पाँच छह8890123456double prefix
one two three four five six123456English digit words

​
6 — Mixed & code-mixed utterances

A single sentence may contain multiple entity types or blend Hindi and English. ITN handles all in one pass, normalizing each entity independently.
Spoken input (ASR)Written output (ITN)
कल थ्री फिफ्टी पीएम को पाँच सौ रुपये transfer करना हैकल 15:50 को ₹500 transfer करना है

​
Native script digits — itn_native_numerals

By default, ITN outputs Western Arabic digits (0–9) regardless of language. Set itn_native_numerals=true to render digits in the native script of the target language.
LanguageSpoken inputfalse (default)true — native script
Hindi hi-INपाँच हज़ार रुपये₹5,000₹५,०००
English en-INfive thousand rupees₹5,000₹5,000 (Latin — no change)

​
What ITN does not change

ITN intentionally preserves idiomatic and ambiguous phrases to avoid incorrect normalization.
  • दो तीन (meaning a few) stays as text, not 2 or 3
  • कर दो / ले दो (imperative verbs) are kept as words, not treated as cardinal 2
If a word or phrase is unchanged in the output, treat it as a failure only when the input was unambiguously a numeric entity.

Find-and-replace (substitution)

Find-and-replace applies on both models and runs after transcription. After transcription (and after ITN, if enabled), the API can apply a custom set of find-and-replace rules to the transcript. Use this to:
  • Normalise domain-specific terms (“rs” → “INR”, “ok” → “acknowledged”)
  • Replace competitor names, internal codes, or product shortforms
  • Standardise phrases that the model consistently transcribes differently from your expected output

​
How to enable

Set enable_substitution=true and pass your rules as a JSON string in substitution_map.

​
Rule format

[
  {"patterns": ["find1", "find2", "find3"], "replacement": "replacement1"},
  {"patterns": ["find4"],                   "replacement": "replacement2"}
]
  • Up to 10 rules per request.
  • Each rule can list any number of patterns that all map to the same replacement.
  • Matching is case-insensitive ("ok" matches "OK", "Ok", "ok").
  • Matching respects Unicode word boundaries — "ok" does not match inside "okay".
  • Longer phrases always match before shorter ones — "New Delhi" is tried before "Delhi".
  • Rules are applied in a single pass with no cascading — a replacement is never re-matched by another rule.

​
Example

curl --request POST \
  --url https://api.vachana.ai/stt/v3 \
  --header 'X-API-Key-ID: <api-key>' \
  --form audio_file='@call.wav' \
  --form language_code=en-IN \
  --form format=transcribe \
  --form enable_substitution=true \
  --form 'substitution_map=[
    {"patterns": ["okay", "ok", "alright"], "replacement": "acknowledged"},
    {"patterns": ["rupees", "rs"],           "replacement": "INR"},
    {"patterns": ["New Delhi", "Delhi"],     "replacement": "NCR office"}
  ]'
Original transcript (from ASR + ITN)After substitution
ok, the payment of ₹500 rupees is doneacknowledged, the payment of ₹500 INR is done
alright, please contact the Delhi branchacknowledged, please contact the NCR office branch
Substitution runs on the final client-visible transcript only. Billing and analytics records always carry the original raw transcript regardless of this setting.

Word boosting (bias_list)

This section describes Prisma v2.5. For Prisma v3.0 use keyterms; see Context. Word boosting nudges the recognizer toward specific words so they are more likely to be transcribed correctly — useful for brand names, product names, and domain terms that are otherwise misheard. It influences recognition itself; it is not a find-and-replace (see Find-and-Replace for that).

​
How to use

Send both fields together:
FieldDescription
bias_listUp to 100 words, as a JSON array or comma-separated string.
bias_score0.0, 0.5, 1.0, 1.5 or 2.0.
bias_scoreEffect
0.0Off (same as omitting it)
0.5Light nudge
1.0Typical starting point
1.5Stronger
2.0Maximum
Start at 1.0 and raise only if a word is still missed — stronger boosting can make the model favour a listed word where it wasn’t spoken.

​
Word rules

  • Each entry is one word. Phrases such as "loan number" are not allowed.
  • Letters only — English letters or letters in the supported Indian scripts. No digits (HDFC2), punctuation (HDFC-EMI), or symbols (@brand).
  • Casing does not matter.
  • Maximum 100 words; any beyond that are dropped.
  • Use format=verbatim. Boost words are spoken-form tokens, so digit strings and normalized numbers won’t work.
  • Use a JSON array if you’d rather not worry about commas; both formats are accepted.
Invalid input does not return an error. If any entry breaks the rules (or bias_score is not an allowed value), the whole list is ignored and the audio is transcribed without boosting, still returning 200. If boosting seems to have no effect, check your list first.

​
When it applies

Boosting applies when language_code is a specific language such as hi-IN or en-IN, and you use Prisma v2.5, the default model (omit model). Batch STT has its own bias_list and bias_score settings; see Word boosting on Batch. The response format is unchanged; boosted words are not echoed back.

​
Example

curl --request POST \
  --url https://api.vachana.ai/stt/v3 \
  --header 'X-API-Key-ID: <api-key>' \
  --form audio_file='@call.wav' \
  --form language_code=en-IN \
  --form format=verbatim \
  --form bias_list=Prisma,Vachana \
  --form bias_score=1.0

​
Behaviour notes (Prisma v3.0)

  • One transcript. On v3.0 transcript is always a string, never a dictionary.
  • An empty transcript is not an error. Log it; do not treat it as a failure.
  • truncated: true means the model hit its token limit and the transcript is incomplete. Retry with shorter audio or split the recording. The field is only present when this happens.
  • Context can lower accuracy — test with and without it.
  • end_to_end_latency includes your upload; processing_time does not.
  • Results for identical audio can differ by a borderline word; cache results if you need stable output.
  • Very short utterances (under about a second) are the least reliable. Silence is detected first, and a clip with no speech returns an empty transcript.
