# ADR-003: PostgreSQL and transactional work orders

Status: Accepted implementation decision, recorded retrospectively on 2026-11-09 from merged code and the roadmap; remaining gaps are not approved away.

## Context
One intake must create at most one durable order with an atomic audit event under races.

## Decision
Use PostgreSQL 18, Alembic, unique intake/idempotency constraints and advisory/row locks.

## Alternatives considered
Browser state or ephemeral local files cannot be authoritative. Schema changes must preserve existing demo records.

## Consequences
Runtime mutations validate catalog relationships; workflow uses expected versions. Audit/provenance triggers reject edits. App rollback requires compatible schema; DB restore is into a new instance.
